# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Two independent parts, both documented for the user in Traditional Chinese:

- `tf-idf.py` (guide: `README.md`): a CLI for SEO content research. For each keyword it gets the top Google results for a location (default Alberta, Canada) from SerpApi, downloads the result pages, and scores the words and two-word phrases the pages share by TF-IDF.
- `site/` (guide: `site/README.md`): a static review site for Alberta's regulated online casinos, generated by `site/build.py` from Markdown and YAML with Jinja2 templates. The site text itself is English.

`docs/alberta-ad-compliance-checklist.md` summarises Alberta's gambling-advertising rules; the site build enforces the machine-checkable parts.

## Commands

```bash
pip install -r requirements.txt
SERPAPI_API_KEY=... python tf-idf.py "alberta online casino" [--results 10] [--out output]
```

There are no tests or linter. Every 10 results cost one SerpApi search credit.

## Behavior that is not obvious from a quick read

- `search_results()` pages through SerpApi with `start` (0, 10, ...) because Google has ignored `num` since September 2025. A non-200 answer is an error (bad key, quota, unsupported location); a 200 answer without `organic_results` means Google has no more results.
- If a search fails, `main()` stops but still writes the CSVs for the keywords already done, since their credits were spent, and then exits 1. Both CSVs are rewritten on every run.
- TF-IDF uses `min_df=2`, so a keyword needs at least two fetched pages that share a term; otherwise it is skipped with a message. Terms containing digits are dropped.
- Stop words are NLTK's English list; `load_stop_words()` downloads it only when missing. Chinese text is not segmented (a run of Chinese characters becomes one token), so the tool is meant for English keywords.
- CSVs are written as UTF-8 with BOM (`utf-8-sig`) so Excel on Windows opens them correctly.
- `tf-idf.py` uses CRLF line endings; preserve them when editing so diffs stay minimal.

## Site (`site/`)

```bash
cd site && pip install -r requirements.txt
python build.py --drafts   # preview into dist-preview/: includes drafts, all noindex, errors become warnings
python build.py            # production into dist/: fails on any error and leaves the old dist/ untouched
```

- `build.py` renders content/ (Markdown with YAML front matter; `{{ site.key }}` placeholders are substituted by regex, not Jinja, so attr_list `{#id}` syntax stays safe) through templates/ with `StrictUndefined`, so every key a template reads must exist; operator dicts get defaults from `OPERATOR_OPTIONAL`.
- Production checks: placeholder values in config.yaml; published operators must have `aigc_listed: true`, a `listing_checked_on` no older than 35 days and https URLs; `HIGH_RISK_PHRASES` in the visible text, title and description unless the page lists the label in `compliance_allow`; exactly one `<h1>`; unique titles and descriptions; `<img>` alt text; internal links must be root-relative and resolve to a built file.
- Affiliate links always go through generated `/go/<slug>/` redirect pages (noindex, disallowed in robots.txt), and `mark_sponsored()` adds `rel="sponsored nofollow"` to any `/go/` link in Markdown.
- CSS in `assets/site.css` is minified and inlined into every page; `static/` is copied as is. Colours follow theme-factory's Ocean Depths, with `--teal-dark` used for text so contrast stays WCAG AA.
- Only write facts that are verified: the guides cite official sources in their `sources` front matter, and operator facts must come from the user's own testing, never invented.

## Running in Claude Code on the web

- serpapi.com and www.google.com are blocked by the sandbox network policy (the proxy returns 403), so real searches cannot run there. To test, replace `requests.get` with a stub that serves both the SerpApi call and the page downloads, then run the script with `runpy.run_path(..., run_name="__main__")`.
- NLTK refuses to download through the sandbox's HTTPS proxy ("Security Violation ... refusing a proxied fetch"); set `NLTK_ALLOW_PROXIED_URLOPEN=1` for the command.
- To audit the site, serve a production build with `python -m http.server` and run Lighthouse from npm with `CHROME_PATH=/opt/pw-browsers/chromium-1194/chrome-linux/chrome` and `--chrome-flags="--headless=new --no-sandbox"`; the global Node `playwright` package (use `NODE_PATH=$(npm root -g)`) works for screenshots. A production build needs a copy of `site/` with real-looking values in config.yaml.
